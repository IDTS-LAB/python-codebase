# UUID → int IDs + Module Facade Pattern

Date: 2026-08-01
Branch: `development`

## Goal

1. Convert all database entity IDs from UUID to auto-increment integers across all modules.
2. Refactor module-to-module communication to use a Facade pattern (per-module public contracts), replacing the current ad-hoc `UserModuleProvider`.

## Decisions (confirmed with user)

| Decision | Choice |
| --- | --- |
| Facade shape | Per-module facades: shared `ModuleFacade` base class, each module exposes `XxxModuleFacade` |
| Migration strategy | In-place alembic conversion (maps old UUIDs to new ints, preserves data and FK relationships) |
| Event IDs | Keep UUID — `event_id` in domain events, audit event ids, `request_id`, JWT `jti` are correlation IDs, not DB keys |

## Part 1: UUID → int

### ID convention

Every DB primary and foreign key becomes `int` (SQLAlchemy `Integer`, autoincrement identity).

- `src/shared/database/model.py` — `Base.id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True, sort_order=-100)` (drop `PG_UUID`, `uuid4`).
- `src/shared/database/mixin/tenant.py` — `tenant_id: Mapped[int]` FK to `tenants.id`.
- Domain entities: `id: int` (user, refresh_token, todo, tenant, role, permission, resource, api_key).
- Repositories, services, handlers, schemas, routers, dependencies: `id: int`, `tenant_id: int`.
- `src/shared/utils/cursor.py` — cursor encodes/decodes `int` ids instead of `UUID`.
- Casbin subjects: `user:{int}` / `role:{int}` — replace `UUID(subject)` with `int(subject)` in `casbin_policy_repository.py`.
- JWT / 2FA / auth: `user_id` becomes int string; `core/dependency/auth.py` `UUID(user_id)` → `int(user_id)`.
- `core/middleware/tenant.py` — parse `X-Tenant-ID` header as int.
- Seeds (`core/seed/tenant.py`, `core/seed/user.py`, `core/seed/authorization.py`, `core/seed/runner.py`) — replace `uuid4()` id generation with explicit ints / DB-generated ids.
- **api_key**: `id` becomes int identity. The `String(36)` PK column in `api_key/infrastructure/models.py` and `UUID` entity type in `api_key/domain/entities.py` both change to `int`. The raw key (`api_…`) remains the secret; the sequential id is only an identifier/subject.
- `UserProfile.id` in the facade becomes `int` (was `str`).

### Stays UUID (not DB IDs)

- `src/shared/events/base.py` — `event_id`
- `src/core/security/audit.py` — event ids
- `src/core/middleware/request_id.py` — request ids
- `src/core/security/jwt.py` — `jti`
- `src/modules/api_key` raw key generation (the `api_…` secret token itself)

### Migration

One new alembic revision, e.g. `convert_ids_to_integer`, performing an in-place conversion for every Base-derived table that has a UUID PK/FK: users, refresh_tokens, user_profiles, user_settings, user_security, user_contacts, user_addresses, user_verifications, tenants, roles, permissions, resources, role_permissions, user_has_roles, todos, api_keys, audit_logs, login_attempts, error_traces. Per table:

1. Add `_new_id` `INTEGER GENERATED BY DEFAULT AS IDENTITY` column.
2. Populate via ordered `row_number()` over the old PK to create a deterministic old-UUID → new-int mapping.
3. For FK columns: add `_new_<fk>` int column, backfill by joining on the mapping.
4. Drop FK constraints referencing the old UUID columns, drop the old columns, rename `_new_*` columns to canonical names, re-create PK/FK constraints.
5. Downgrade reverses the process (mapping preserved through the int→uuid column).

The migration must keep data and referential integrity. It runs in both `upgrade()` and `downgrade()`.

## Part 2: Module facade pattern

### New shared base

- `src/shared/facade.py` — `class ModuleFacade(ABC)` (or simple marker base): the public contract a module exposes to other modules.

### User module facade

- Refactor `src/modules/user/providers.py` → `src/modules/user/facade.py`:
  - `class UserModuleFacade(ModuleFacade)` with the same public API (`get_user_profile(user_id: int) -> UserProfile | None`).
  - `UserProfile.id: int`.
- Update consumers:
  - `src/core/dependency/providers.py` — rename file to `src/core/dependency/facades.py`, factory renamed `get_user_module_facade` returning `UserModuleFacade`.
  - `src/modules/todo/presentation/dependency.py` and `src/modules/todo/application/detail_todo/handler.py` — import and type against the facade only.
  - `src/modules/user/__init__.py` — re-export facade.
- Keep a `UserModuleProvider` → remove; rename import sites.

### Import-linter contracts

Tighten `.importlinter` so other modules may only import `src.modules.<module>.facade` (the public contract), never internals (`application`, `domain`, `infrastructure`, `presentation`). Existing contracts already approximate this; add the `facade` as the only allowed import path for cross-module access.

### Scope

Only `user` gets a facade now (it is the only module consumed cross-module, by `todo`). Other modules get facades when cross-module communication exists — YAGNI.
